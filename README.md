# 修图台 · Photo Studio

[![CI](https://github.com/qianc7001-coder/photo-studio/actions/workflows/ci.yml/badge.svg)](https://github.com/qianc7001-coder/photo-studio/actions/workflows/ci.yml)
[![License: MIT](https://img.shields.io/badge/License-MIT-blue.svg)](LICENSE)
[![Tests](https://img.shields.io/badge/tests-802%20passed-brightgreen.svg)](#测试)

给摄影师用的**局部修图**工具：在照片上框选任意区域，交给生图模型修改，结果自动贴回原位置。

**核心特点**：结果无缝融合，非破坏性可调，保留拍摄信息。

> 最新版本 **v2.3.0** · [下载 APK](https://github.com/qianc7001-coder/photo-studio/releases/latest) · [更新日志](CHANGELOG.md)

---

## 它解决什么问题

传统流程：导出照片 → 用别的工具涂涂抹抹 → 再导入 → 手动对齐 → 接缝对不上。

修图台的做法：

```
打开照片 → 框选要改的地方 → 写一句要求 → 生成 → 自动贴回原位置
```

贴回时做了**边缘羽化**和**接缝色彩匹配**，所以看不出拼接痕迹。

## 功能

### 编辑
- **自由框选**：任意位置、任意大小，支持拖拽手柄调整、锁定比例
- **画笔**：涂抹标记"这里不要动"（默认整块都会改）
- **缩放平移**：双指缩放、拖拽平移，最高 12 倍放大

### 非破坏性
- **修改记录面板**：每次生成是一条独立记录
- 可随时调整**效果强度 / 边缘羽化 / 色彩匹配**，**不需要重新生成**（不花钱）
- 可**临时关闭**某次修改做前后对比，可**删除**中间任意一次

### 统一撤销
画笔、删除、调参、开关**全部可撤销/重做**（100 步历史）。

### 修图历史
- **完整时间线**：按顺序列出做过的每一步，每步带摘要（改了什么、当时有几处修改、几点做的）
- **预览任意一步**：点时间线上任意位置，画面真的回到那一刻，先看效果再决定
- **一键跳回**：确认后回到选中的那一步，后面的步骤被撤销（确认前随时能跳回来）
- 不存图片快照，只复用撤销记录 —— 100 步历史几乎不占额外内存

### 画质
- 边缘羽化（消除拼接硬边）
- 接缝色彩匹配（把生成结果色调对齐原图）
- 细长选区自动按比例裁切贴合，**不会变形**
- 大选区自动分块 + 重叠区加权融合，**块间无缝**
- 小选区自动放大后发送（应对接口最小尺寸限制）

### 元数据
- 导出保留 **EXIF**（相机、镜头、光圈、快门、ISO、拍摄时间）
- 保留 **ICC** 色彩配置
- 手机竖拍照片的旋转标记正确归一化（不会二次旋转）
- 社交分享时可**自动移除 GPS 定位**（保留其他信息）

### 稳定性
- 编辑历史内存上限（默认 192MB，可调）—— 防止手机被系统杀掉
- 编辑进度自动保存 —— 应用被回收后可恢复
- 导出预设（客户交付 / 微信 / 小红书 / 网页 / 无损交接）

### 模型接入
- 多服务商：硅基流动 / OpenAI / 任意 OpenAI 兼容接口
- **自动检测可用模型**（自动筛出支持参考原图编辑的模型）
- **成本预估**：生成前显示花费，大额自动确认
- 失败原因诊断（区分模型选错、没收到图片、Key 失效、限流、尺寸不合规等）

## 快速开始

### 方式一：安装 APK（推荐）

1. 安装 `修图台.apk`（Android 7.0+）
2. 打开应用 → 右上角「设置」
3. 填「接口地址」和「API Key」
4. 点「自动检测可用模型」，选一个标着**可编辑**的模型
5. 回主界面：打开照片 → 框选 → 写要求 → 点「生成并贴回」

**推荐模型**（支持参考原图编辑）：

| 服务商 | 模型 | 单价参考 |
|---|---|---|
| 硅基流动 | `Qwen/Qwen-Image-Edit` | $0.04/张 |
| 硅基流动 | `black-forest-labs/FLUX.1-Kontext-pro` | $0.04/张 |
| OpenAI | `gpt-image-1` | $0.042/张 |

> 注意：像 `deepseek-chat`、`gpt-4o` 这类是**对话模型**，只会回文字，不能用于修图。

### 方式二：浏览器打开（无需安装）

```bash
node app/server.js 8788
# 然后用手机浏览器打开 http://127.0.0.1:8788
```

或直接打开 `dist/修图台.html`（单文件版，离线可用）。

## 从源码构建

### 环境要求

- **Node.js** 18+
- **JDK 17**（`apt install openjdk-17-jdk-headless`）
- **Android 工具**：`apt install aapt zipalign`，另需 `d8.jar` / `apksigner.jar` / `android.jar`
  （来自 Android SDK build-tools 与 platform，放在 `/root/android-sdk`，可用 `ANDROID_SDK` 环境变量覆盖）

### 构建

```bash
# 构建 APK（自动递增版本号）
bash tools/build-apk.sh

# 只构建单文件 HTML
node tools/build-single.js

# 版本号检查（不改文件）
node tools/bump-version.js
```

产物：
- `dist/修图台.apk` — 安装包
- `dist/修图台-v<版本>.apk` — 带版本号的副本
- `dist/修图台.html` — 单文件网页版

### 版本号管理

`version.json` 是**唯一版本来源**，构建时自动写入 `AndroidManifest.xml` 和页面。

`tools/bump-version.js` 会比对源码指纹：
- 内容变了但版本号没变 → **自动递增**
- 内容未变 → 沿用同号
- 首次构建 → 只记录基准，不改号

## 项目结构

```
app/
  core.js        纯逻辑：几何变换、羽化合成、色彩科学、模型接入、成本预估…
  app.js         应用主体：交互、画布、生成流水线、UI
  index.html     界面结构
  style.css      样式
  server.js      本地服务（静态托管 + 同源代理，解决跨域）
  version.js     版本号（构建时自动生成，勿手改）

  src/           Android 外壳（WebView + 内置 HTTP 服务）
  res/           图标与主题

  build-single.js 打包单文件 HTML
  bump-version.js 版本号自增守卫
  core-test.js / regression-test.js / e2e-test.js  测试
```

### 架构说明

**为什么 Android 版内置一个 HTTP 服务？**

WebView 里用 `file://` 打开页面时，跨域请求会被拦截，而且 `localStorage` 的源不稳定（随机端口会导致设置丢失）。

所以应用启动时在 `127.0.0.1` 起一个**只监听本机**的极简 HTTP 服务：
- 页面与接口同源 → 没有跨域问题
- 固定端口 → 设置能稳定保存
- 生图请求由本机服务转发 → API Key 不经过第三方

## 设计要点

### 贴回为什么看不出接缝

1. **上下文外扩**：发送时把选区周边的环境一起发给模型，让它理解光线和色调
2. **边缘羽化**：选区边界做平滑过渡，不是硬切
3. **接缝色彩匹配**：采样选区内外一圈像素，算出色差，在边缘附近渐进补偿
4. **精确坐标映射**：模型返回的尺寸和比例往往与选区不同，按「盖满 + 居中裁切」取回，**不会拉伸变形**

### 为什么调参不用重新生成

羽化、色彩匹配、效果强度这些参数是在**合成时**应用的，不是烧进生成结果里的。
所以拖动滑块只是重新合成一遍（毫秒级），完全不调用模型。

### 隐私

- 照片只发送到**你自己配置的接口地址**，应用本身不做任何上传
- 可选：发送前对选区外的无关区域打码
- 社交导出预设会自动移除 GPS 定位

## 常见问题

**生成报 `upstream_text_reply`（上游回了一段文字）**

说明当前模型是**对话模型**，不是生图模型。到设置里点「自动检测可用模型」，选标着「可编辑」的。

**报「出图尺寸不符合接口要求」**

不同接口对尺寸有硬性约束（如 OpenAI 要求总像素 ≥ 0.66MP、宽高为 16 的倍数）。
应用会自动修正，若仍报错请把「工作分辨率上限」调低。

**导入大照片后卡住**

把「工作分辨率上限」调到 2048。大照片（如 4800 万像素）解码很吃内存。

**小选区效果不好**

小选区放大后发送，细节上限受原图那一小块的信息量限制。
可以试试换用支持更大输出的模型，或先放大选区再生成。
